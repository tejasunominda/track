# TrackForge — Missing Features Roadmap

This document tracks the gaps between the current implementation and a production-grade Jira-equivalent platform. The 18 documented epics are scaffolded or MVP-complete; the work below hardens them into a shippable product.

## Current State

- All 18 feature-ticket epics have backend code.
- Epics 1–12 are functionally usable (auth, projects, issues, workflows, boards, sprints, notifications, reports, search, dashboards).
- Epics 13–18 have enterprise/Phase 2 stubs (SSO, audit log Kafka, webhooks, workflow builder, service desk, portfolio, billing tiers).
- Backend compiles (`mvn package`) and frontend builds (`npm run build`).

## Missing Features by Phase

### Phase 1 — Issue Collaboration (F5-03..F5-05, F5-08)

**Goal:** Make issues feel like Jira issues.

- [x] Issue comments (CRUD, author, timestamps)
- [x] Attachments (local storage, virus scan stub, download)
- [x] Issue linking (blocks/is/relates-to/parent-of with link types)
- [x] Sub-tasks (hierarchy, parent roll-up via parentId)
- [ ] Watchers / votes / labels UI and API
- [ ] Inline editing of summary, assignee, priority, story points

### Phase 2 — Real-Time Board & Sprint Experience (F6, F7)

**Goal:** A usable Scrum/Kanban board and sprint workflow.

- [x] Drag-and-drop board with `@dnd-kit` (frontend)
- [x] WebSocket/STOMP for live card moves
- [x] Issue rank / LexoRank ordering
- [ ] Backlog view and sprint planning drag-and-drop
- [ ] Sprint board with swimlanes and WIP limits
- [ ] Active-sprint auto-start / complete with real incomplete-issues logic

### Phase 3 — Search, TQL, and Elasticsearch (F10, F11)

**Goal:** Jira-equivalent search and query language.

- [x] TQL autocomplete API

- [ ] Global search UI with faceting

### Phase 4 — Frontend Application Parity (F2-04, F3-03/04, F5-06..09)

### Phase 5 — Integrations (F13, F15)

**Goal:** Connect TrackForge to the rest of the toolchain.

- [ ] Email notifications (SMTP)

- [ ] GitHub/GitLab/Bitbucket issue-linking and smart commits
- [x] Webhook event dispatch for issue/comment/sprint events
- [ ] Webhook payload templates and retries

### Phase 6 — Enterprise Hardening (F13, F18)

**Goal:** Production and enterprise readiness.

- [ ] Real SAML2/OIDC relying party integration

- [x] Audit log CSV export
- [ ] GDPR export and right-to-be-forgotten flows
- [ ] Stripe Checkout + subscription lifecycle
- [ ] Real Kubernetes/Terraform deployment
- [ ] Comprehensive integration tests and load tests

## Suggested Build Order

1. **Issue comments** — highest user value, simple backend.
2. **Attachments** — requires S3 wiring, good to do next.
3. **Issue links + sub-tasks** — completes the issue model.
4. **OpenAPI-generated client + basic React pages** — unlocks frontend velocity.
5. **Drag-and-drop board + backlog** — highest visual Jira parity.
6. **Elasticsearch + TQL** — moves search from toy to tool.
7. **Integrations and enterprise features** — last, as they depend on external systems.
